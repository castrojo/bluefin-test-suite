# Skill Discovery Index Design

## Goal

Add a machine-readable, lazy-loading catalog beneath the existing
`agents.md` -> `docs/skills/index.md` documentation flow. Agents should be
able to filter available skills without loading skill bodies, while the
catalog remains generated from each skill's YAML front matter.

## Scope

The catalog includes only loadable `docs/skills/**/SKILL.md` pages. Reference
pages remain on-demand content linked from their parent skill and are not
separate catalog entries.

## Architecture

Each catalogued `SKILL.md` carries a required front-matter contract:

- `id`
- `name`
- `one_line_purpose`
- `entry_point`
- `category`
- `mcp_compliance_level`
- `optimization_status`
- `dependencies`
- `tags`

The `id` is a stable, lowercase hyphenated identifier. `name` is the display
name and may change without changing `id`. The generator reads front matter,
normalizes the entry point relative to the repository root, validates all
metadata and dependencies, and writes `docs/skills/index.json`.

The JSON catalog contains only the fields above plus no inline skill content.
`docs/skills/index.schema.json` is the source of validation rules and defines
JSON Schema 2020-12. Categories are intentionally small and orthogonal:
`ci-ops`, `test-authoring`, and `meta`. Compliance is graded as `none`,
`partial`, or `full`; optimization is graded as `draft`, `reviewed`, or
`optimized`. Existing skills default conservatively to `partial` and `draft`
unless their current documentation demonstrates otherwise.

## Data flow

1. An agent reads root `agents.md`.
2. It reads `docs/skills/index.json` for machine filtering, or
   `docs/skills/index.md` for human routing.
3. It filters entries by category, compliance, optimization status, or tags.
4. It loads only selected `entry_point` files.
5. CI regenerates and validates the catalog, failing if generated output,
   front matter, paths, enums, ids, or dependencies are invalid.

The checked-in JSON is deterministic and CI compares the generated bytes with
the committed file, preventing drift.

## Components

- `scripts/generate_skill_index.py`: parse front matter, validate metadata and
  dependency references, emit JSON, and validate against the schema.
- `docs/skills/index.schema.json`: machine-readable contract and enum
  definitions.
- `docs/skills/index.json`: generated discovery catalog.
- `docs/skills/skill-index-maintenance.md`: contributor procedure and command.
- `docs/skills/*/SKILL.md`: metadata source of truth.
- `.github/workflows/docs-validate.yml`: generation and validation gate.
- `agents.md`: minimal discovery instructions linking both manifests.

## Error handling and compatibility

The generator fails loudly for malformed front matter, missing required
fields, invalid enum values, duplicate ids, invalid id syntax, missing entry
points, dependencies that do not resolve to another skill id, or schema
validation failures. Renaming a display name or changing a category/compliance
level does not change the stable id. Deprecation preserves the id and is
documented in the maintenance skill; this design does not add extra
top-level catalog fields beyond the requested minimal payload.

## Validation

The existing docs validator remains responsible for Markdown structure and
generic front matter checks. The new generator owns the stricter index
contract. Docs CI runs both checks. The targeted local command is:

```bash
python3 scripts/generate_skill_index.py --check
```

The `--check` mode regenerates in memory, validates against the schema, and
fails if `docs/skills/index.json` differs.

## Research basis

Context7's MCP documentation describes lightweight search results containing
names and one-line descriptions, then on-demand resource reads; this supports
the minimal catalog and `entry_point` design. OpenAI Agent Skills guidance
uses required `name` and `description` front matter and a three-level
progressive-disclosure model. MCP's current schema guidance identifies JSON
Schema 2020-12 as the default dialect for embedded schemas.
