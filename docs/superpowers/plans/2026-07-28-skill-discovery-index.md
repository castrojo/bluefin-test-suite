# Skill Discovery Index Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and CI-enforce a generated JSON skill catalog sourced from `SKILL.md` front matter and exposed through the AAIF root agent entry point.

**Architecture:** Extend the existing Python/PyYAML documentation tooling with a focused generator that parses only `docs/skills/**/SKILL.md`, validates metadata and dependencies against a JSON Schema 2020-12 contract, and emits deterministic `docs/skills/index.json`. Add the catalog metadata to every loadable skill, document maintenance in a meta-skill, and run generation in docs CI with a drift check.

**Tech Stack:** Python 3.14, PyYAML, JSON Schema 2020-12, GitHub Actions, Markdown YAML front matter.

## Global Constraints

- Catalog only `docs/skills/**/SKILL.md`; reference pages remain on-demand.
- Front matter is the sole source of catalog metadata; never hand-edit `docs/skills/index.json`.
- Keep catalog entries limited to `id`, `name`, `one_line_purpose`, `entry_point`, `category`, `mcp_compliance_level`, `optimization_status`, `dependencies`, and `tags`.
- Preserve stable ids across display-name, category, and compliance changes.
- Fail loudly on missing metadata, invalid enums, duplicate ids, broken entry points, dangling dependencies, and schema failures.
- Preserve existing user changes in the dirty worktree; modify only files required by this feature.
- External GitHub Actions references must remain pinned to full commit SHAs with version comments.

### Task 2: Implement the generator and validator

**Files:**
- Create: `scripts/generate_skill_index.py`
- Modify: `tests/unit/test_generate_skill_index.py`

**Interfaces:**
- Consumes the schema and front matter fixtures from Task 1.
- Produces deterministic JSON with the shape `{"skills": [...]}` and a `--check` mode that compares generated bytes to `docs/skills/index.json` without modifying it.

- [ ] **Step 1: Implement front-matter parsing using the existing delimiter convention**

Reuse the `---` YAML convention from `scripts/validate_docs.py`; reject files that lack a mapping front matter block. Require `id`, `name`, `one_line_purpose`, `entry_point`, `category`, `mcp_compliance_level`, `optimization_status`, `dependencies`, and `tags`.

- [ ] **Step 2: Implement path, id, enum, duplicate, and dependency validation**

Require ids to match `^[a-z0-9]+(?:-[a-z0-9]+)*$`, require `entry_point` to equal the current skill path and exist, reject duplicate ids, and resolve dependencies only against the collected skill ids. Normalize missing optional lists only where the schema explicitly permits an empty list; do not silently downgrade invalid values.

- [ ] **Step 3: Implement schema validation with the `jsonschema` dependency**

Use `jsonschema.Draft202012Validator` against `docs/skills/index.schema.json`. Add `jsonschema` to the docs CI install step and document it as the generator's validation dependency. Keep errors actionable and non-silent.

- [ ] **Step 4: Implement `--write` and `--check`**

`--write` validates and writes formatted JSON with a trailing newline. `--check` validates the generated in-memory document, reads the committed catalog, and exits nonzero with a drift message when bytes differ. Default invocation should be `--write` for local regeneration.

- [ ] **Step 5: Run the focused tests to verify they pass**

Run: `python3 -m pytest tests/unit/test_generate_skill_index.py -q`

Expected: PASS for valid generation and all failure cases.

- [ ] **Step 6: Commit the implementation**

```bash
git add scripts/generate_skill_index.py tests/unit/test_generate_skill_index.py
git commit -m "feat: add generated skill index validator"
```
